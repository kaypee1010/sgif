## What is SGIF in one paragraph

SGIF is your personal teaching platform built on Google Sheets + Google Apps Script. Every quiz a student takes — whether a post-lecture MCQ, a lab evaluation, or a CodeChamps competition — automatically saves their score, their answers, their topic accuracy, and their confidence ratings into one Google Sheet. Over time this builds a growth record for every student. You get a faculty dashboard to see which topics your class struggles with. Students get a self-service portal to see their own progress.

---

## The one Google Sheet

Everything lives in **one Google Sheet, forever**. Never create a second one.

| Tab | What it stores | Who writes to it |
|---|---|---|
| **Config** | Settings (institution name, api_key) | You, manually |
| **Audit** | Every API call, automatically logged | Code.gs |
| **Responses** | Every quiz attempt — lecture, lab, and event | Quiz HTML files |
| **Events** | Every click, navigation, tab-switch during quizzes | Quiz HTML files |
| **Students** | Your class rosters | You, by upload |
| **Activities** | Competition/event registry | You, manually |
| **Registrations** | Student signups for competitions | student_registration.html |

## The generated files (one per quiz)

Every lecture quiz, lab quiz, and competition quiz is a fresh HTML file generated by pasting the **Master Prompt** into a Claude conversation. You answer ~10 questions and Claude produces the complete file.

| Quiz type | Example filename | Example Quiz_ID | Example Cohort_ID |
|---|---|---|---|
| BTech Sem 7 MATLAB Lecture 1 | `matlab-l1.html` | `MATLAB-L1` | `BTECH_SEM7_2025` |
| BTech Sem 7 MATLAB Lab 1 | `matlab-lab1.html` | `MATLAB-LAB1` | `BTECH_SEM7_2025` |
| BTech Sem 5 AI/ML Lecture 3 | `aiml-l3.html` | `AIML-L3` | `BTECH_SEM5_2025` |
| BCA Sem 3 Intro to AI Lecture 1 | `introa-l1.html` | `INTROA-L1` | `BCA_SEM3_2025` |
| BSc Sem 1 C Programming Lecture 2 | `cprog-l2.html` | `CPROG-L2` | `BSC_SEM1_2025` |
| CodeChamps Round 1 | `codechamps-01.html` | `CC-01` | `SGT_LEAGUE_2025` |
| Aptitude Arena Round 1 | `aptarena-01.html` | `APT-01` | `SGT_LEAGUE_2025` |

**Naming rules:**
- Quiz_ID: `[SUBJECT]-[TYPE][NUMBER]` — short, no spaces, uppercase
- Cohort_ID for classes: `[BRANCH]_SEM[N]_[YEAR]`
- Cohort_ID for events: `SGT_LEAGUE_[YEAR]` — same for all competitions that year
- Filename: lowercase version of Quiz_ID with `.html`

After generating, open the file and set these three constants at the top of the script:
```javascript
const API_URL   = 'your /exec URL here';
const QUIZ_ID   = 'MATLAB-L1';
const COHORT_ID = 'BTECH_SEM7_2025';
```

## Cohort_ID — the most important concept to get right

Cohort_ID is the label that groups students together for filtering and analysis.

**For lecture/lab quizzes:** Cohort_ID = Branch + Semester + Year. All quizzes for that class share the same Cohort_ID all semester. Example: every MATLAB lecture and lab for BTech Sem 7 uses `BTECH_SEM7_2025`.

**For events/competitions:** Cohort_ID = `SGT_LEAGUE_2025`. All competitions in the academic year share this. It lets you later ask "which students participated across the most event formats?"

**Never change a Cohort_ID mid-semester.** If you do, the dashboard filter breaks and students appear to be in two different cohorts.

## The Students tab — your class rosters

At the start of each semester, upload your class rosters to the Students tab. This enables the **auto-fill feature**: students enter only their roll number at the start of a quiz, and their name/branch/semester pre-fills automatically.

**Columns required:**

| Roll Number | Name | Section | Branch | Semester | Cohort_ID | Status |
|---|---|---|---|---|---|---|
| 241302001 | Arjun Sharma | A | BTech CSE | 7th | BTECH_SEM7_2025 | Active |
| 241302002 | Priya Verma | B | BTech CSE | 7th | BTECH_SEM7_2025 | Active |
| 231201001 | Neha Singh | A | BCA | 3rd | BCA_SEM3_2025 | Active |

All your classes go into **the same Students tab** — just with different Cohort_IDs. You can have BTech Sem 7 and BCA Sem 3 rows side by side; the Cohort_ID separates them when filtering.

**How to upload:** Export your attendance register as CSV → paste into the Students tab after the header row → ensure Roll Number column matches exactly what students type (no spaces, consistent format).

## Workflow A — Running a lecture or lab quiz

**Before the semester (once)**
1. Upload class roster to Students tab with correct Cohort_ID
2. That's it — no other setup needed

**Per quiz (takes ~15 minutes)**
1. Open a Claude conversation, paste the Master Prompt
2. Select **Lecture Mode** or answer questions for Lab Mode
3. Provide: subject, topics, number of questions, Quiz_ID, Cohort_ID, your API URL
4. Claude generates a complete `.html` file
5. Open the file, confirm `API_URL`, `QUIZ_ID`, `COHORT_ID` at the top
6. Push to GitHub Pages (`matlab-l1.html`)
7. Share the URL in class on the projector

**During the quiz**
- Students open the URL, enter roll number, details auto-fill, they begin
- Rows appear live in Responses and Events tabs as students submit
- No action needed from you

**After the quiz**
- Open `faculty_dashboard.html`
- Filter by Cohort_ID and Quiz_ID
- See: average score, pass rate, hardest topics → plan next lecture accordingly

## Workflow B — Running a competition event

**Two weeks before (setup)**
1. HOD approval — get the date and venue
2. Add one row to the Activities tab:
   - Activity_ID: `CODECHAMPS-01`
   - Title: `CodeChamps — Round 1`
   - Type: `CodeChamps`
   - Status: `DRAFT`
   - Eligibility, capacity, registration window dates
3. Generate the quiz HTML using Master Prompt (Event Mode)
   - Quiz_ID: `CC-01`
   - Cohort_ID: `SGT_LEAGUE_2025`
   - Scoring: Weighted
4. Set API_URL, QUIZ_ID, COHORT_ID in the generated file
5. Push quiz HTML to GitHub Pages
6. Keep quiz URL secret until event day

**One week before (announce)**
1. Change Activities tab row Status: `DRAFT` → `OPEN`
2. Share `student_registration.html` URL — students register, get Registration IDs
3. Watch seat count fill up

**Event day**
1. Change nothing in the sheet or files today
2. At start time: share quiz URL on projector
3. Students play — results appear live
4. At the end: announce top 3 from the leaderboard (already live)
5. Every student has their PDF scorecard automatically

**After the event**
1. Change Activities tab Status: `OPEN` → `DONE`
2. Faculty dashboard → filter Cohort_ID = SGT_LEAGUE_2025
3. See which topics the whole cohort struggled with
4. Post one insight to class WhatsApp — markets the next event

## The api_key — what it is and who needs it

The `api_key` is set once in the Config tab (Key = `api_key`, Value = your chosen password).

| Who | Needs api_key? |
|---|---|
| Students taking a quiz | No |
| Students using student.html | No |
| Students registering for events | No |
| You using faculty_dashboard.html | Yes — enter it in the API Key field |
| You calling participants or students endpoints directly | Yes — add `&key=yourkey` to the URL |

Never put the api_key inside any HTML file that students access.

## What the Master Prompt generates (and what it does NOT)

**Generates:**
- Complete single-file quiz SPA (HTML + CSS + JS)
- All questions, options, scoring logic
- Analytics event logging (17 event types)
- Leaderboard widget (reads live from Foundation)
- PDF scorecard on submission
- Calibration snapshot on result screen (if research mode ON)

**Does NOT generate:**
- Code.gs (backend already exists — never regenerated)
- student_registration.html (permanent — never regenerated)
- student.html (permanent — never regenerated)
- faculty_dashboard.html (permanent — never regenerated)

**Two modes:**
- **Lecture Mode** — 10 rhetorical style sections (Analogy, Witty, Riddle, Scenario, Misconception, Debug, Application, Definition, Sequence, Cause→Effect). Used for post-lecture evaluation.
- **Event Mode** — DIFFICULTY+ sections (Warm-up, Core, Challenge, Tiebreaker). Weighted scoring. Used for competitions.

## Troubleshooting — most common issues

**Leaderboard shows nothing**
The Responses tab header row is missing. Insert the header row manually (see RESPONSE_HEADERS_ in Code.gs for the exact column names), then redeploy.

**Auto-fill doesn't work for a student**
Their roll number in the Students tab doesn't match what they typed exactly. Check for leading zeros, spaces, or capitalisation differences.

**Faculty dashboard shows no data**
Either the api_key is wrong, or the Cohort_ID filter doesn't match what's in the Responses tab. Leave Cohort_ID blank to see all data first, then narrow down.

**PDF doesn't download**
html2pdf.js CDN may be blocked on the student's network. The PDF button on the result screen lets them retry manually.

**Student says they took the quiz but no row in Responses**
The quiz HTML uses `fetch` with `mode:'no-cors'` — the POST goes through but you get no confirmation. If the row is missing, the student likely closed the browser before submission completed. Events rows may still be there even when the Responses row is absent.
